Principal PM 判断

它把「一个工作区」拆成四层同构（数据/智能/执行/界面），再用四种封装（项目/agent/自动化/app）把同一份对象图卖四遍；护城河不在模板数量，在「结果回流成记忆」这条环。

拔电测试判为原生：拿走 agents、automations 与 Genesis 一句话建站，剩下的是一张任务表加十种视图，价值掉一半——因为它卖的就是「不用写代码也有一个 app」。但要看清楚它的 AI 是什么：不是模型能力，是「任务到模型的路由」（TSK 阶梯）加上把业务流程塞进可控容器的工程能力。这也解释了它为什么敢同时卖模板、卖 agent、卖 app——它们本来就是同一份数据的不同壳。

01

产品快照

它到底是什么

抛开营销话术 — 把这个产品当成一个「系统」来看，它到底是什么。

产品定位：官方定义原文是 Taskade is an AI-native workspace. Taskade Genesis turns one prompt into a live, hosted app. Each app runs on Workspace DNA: Projects hold the data, AI agents add intelligence, and automations act across 100+ integrations。它在 SKILL.md 里写得更直白：The user is usually a business owner, not a developer。换成人话：给「有业务流程但没有工程师」的人，一句话生成一个能跑、能发布、能读写数据的 app。

核心用户承诺

官方主张是「把业务流程变成 live app」。用户语言：你不用先学一套工具，也不用找人开发——把流程说出来，它给你一个带数据表、带 agent、带自动化、能挂自己域名的 app，然后你可以克隆别人的成品改一改。

品类 & 定位

它站在三条货架的交口：协作与项目工具（Notion、Asana、ClickUp、Monday）、自动化平台（Zapier、Make）、以及 no-code app builder（Softr、Bubble、Glide）。位置上它在中间偏「系统」：比协作工具多执行与界面，比自动化平台多数据层，比 app builder 多内建的数据与 agent。这个「中间位」既是它的差异，也是它的解释成本。

前提假设

  • [推断] 「28,602 页」证明的是页面规模，不是流量。程序化 SEO 的有效性取决于这些页有没有排名，而本期未取 Similarweb / Ahrefs 类数据，所以不能据此推断它的自然搜索表现。
  • [推断] 它的收入主力是 Business 与 Pro，而不是 Free/Starter：依据是 Business 档的定位写的就是 For agencies and client work（无限域名 + 白标 + SEO + 10,000 runs），而 Free 只有 3 个 app、10 次自动化，跑不了第二个客户。

02

目标用户 & Jobs-to-be-Done

谁 + 为什么

主要用户分层

  • 小团队 / 一人公司 / 代理机构（business owner, not developer） — 这是它自己写明的 ICP。他们要的不是「更好的项目管理」，是「客户门户 / CRM / 发票流程 / 预约 / 仪表盘」这类小系统，而买一套 SaaS 要钱、找人开发要时间。Free 档的 3 个 app 额度正好够试一个真实场景，Pro 的 10 个自定义域名正好够接客户。
  • 创作者（App Kit 作者） — App Kit 可以把「app 界面 + projects + agents + automations」打成一包，设成免费或付费，别人一键克隆，作者从 Earnings 提现；同一份 app 还可以出 free 与 Pro 两个条目。所以它同时是一个创作者分发平台——sitemap 里 495 个作者页就是证据。
  • 想搬家的团队（Notion / Asana / ClickUp / Trello / Monday 用户） — 它做了 30+ 个导入器（Notion、Asana、ClickUp、Trello、Monday、Zapier、Make、Obsidian、Evernote、Roam、Logseq、Workflowy、Miro…），导入即成为 project，可立刻挂 agent 与自动化。对比页里 155 条 free-<竞品>-alternative 正是给这批人搜的。

触发 & 场景

触发时刻： 业务里同一个流程第三次靠人肉跑：客户问进度要手打、发票逾期要手催、入职清单要人盯。这时候人会去搜「有没有现成模板」，而它 3,997 个模板页 + 4,526 个生成器页就是为这个搜索准备的。

使用频次： 按业务流程频次走（工单/订单/客户跟进落在日到周的量级）；官方未披露使用频次，只披露累计执行量 3M+。

使用场景： 桌面/移动/浏览器扩展；数据在 Projects（10 种视图：List / Board / Table / Mind Map / Docs / Calendar / Gantt / Actionsheet / Org Chart 等）；判断在 Agents（指令 + 知识 + 持久记忆 + 工具 + slash 命令）；执行在 Automations（4 类触发 + 5 类动作 + 分支/循环/过滤/审批）；界面在 Genesis App（可发布到 *.taskade.app 或自有域名）；外部调用走 Hosted MCP 与 REST API。

Jobs-to-be-Done · 用户「雇佣」这个产品去做什么

功能层
把「一个业务的流程」变成「一个能跑的系统」：数据有地方存、判断有人做、重复动作自己跑、界面能给客户看。
"当 ___ 的时候，我想要 ___，这样我就能 ___。"
情感层
不用承认自己请不起开发。它对用户的情绪承诺是「你也能做出一个软件」——这也是 Genesis 一句话生成最上瘾的地方：从想法到能点，中间没有排期。
"我想要感受到 ___ / 避免感受到 ___。"
社交层
在小团队里成为「把流程跑起来的人」；对客户，交付的不是一份文档，而是一个能登录、能提交、能看进度的门户。
"我想要别人把我看成 ___。"
03

核心产品循环

系统动力学

引擎 — 一次使用如何滚成留存，运气好还能滚成增长。

触发 · Trigger
重复的活儿又来了
触发点不是「我要用 AI」，是「这件事每周都要做一遍，而每次都是人在做」。它把触发做成四种：Taskade 内部事件（任务新增/完成/指派/字段变更）、外部 app 事件（Gmail / Slack / GitHub / Notion…）、时间（Schedule）、入站（Webhook / Mailhook / Form）。
→
行动 · Action
要么让 agent 做，要么让自动化跑
同一个流程有两条入口：人问 agent（它带知识、带记忆、带工具，工具可设「自动执行」或「需人工批准」）；或者系统跑 automation（触发 → 动作，中间可插分支、循环、过滤、延时、审批）。两条入口共享同一份数据，所以「先手动跑通，再让它自动跑」是这个产品最自然的学习路径。
→
奖赏 · Reward
产物落回项目里，而不是落在聊天窗口
agent 的产出可以写回 Projects（建任务、改字段、加评论），automation 的产出可以是新记录、通知、邮件、报告；Genesis App 则是把这些能力包成一个界面给终端用户。产出留在数据层，是 Living Loop 能成立的前提。
→
回访 · Return
记忆变厚，下一次判断更准
回来的理由不是「再生成一次」，是「它记得上次是怎么处理的」。持久记忆存成 Project，可浏览可编辑可 fork；知识源可以挂文件、项目、网页、YouTube、云盘（付费档 50 个/agent）。用得越久，越不像一个通用助手。
"它真正教用户的是「流程本身就是产品」：当你把一次处理写成一条 flow，你就有了一个可以交给别人、交给 agent、交给客户的资产。"

获取循环

流量曝光：三合一结构，全部可数。① 程序化 SEO：28,602 条 URL 里 64.2% 是 templates / agents / automate / prompts / convert / generate 这类「搜什么有什么」的资源页；② UGC 克隆工厂：6,135 个社区 app 页 + 495 个作者页进 sitemap，且每个用户发布的 app 自动带 robots.txt / sitemap.xml / llms.txt——客户的产出变成新的发现节点；③ AI 原生发现层（GEO）：llms.txt（2026-11-18 更新，含 TL;DR、事实、FAQ、How to Cite Taskade 的指定引用措辞）、SKILL.md（给 agent 的操作手册）、Hosted MCP（OAuth 2.0 + PKCE）、.well-known 元数据（api-catalog、mcp.json、server-card、agent-skills 索引）、Accept: text/markdown、OpenAPI JSON、TSK-Bench，以及 robots.txt 里写明 ai-train=yes, search=yes, ai-input=yes。

激活 · Aha 时刻

官方叙事里最像 aha 的一刻：一句话 → 一个有数据表、有 agent、有自动化、能发布的 app，从想法到能点中间没有排期。本期未实测，这一点只据官方 llms.txt 与 About 页描述，不作体验结论。

留存驱动

  • 数据 + 记忆都在工作区里：Projects 存业务数据，agent 的持久记忆也存成 Project，搬走等于重建整个上下文。
  • 自动化一旦跑起来就是流程的一部分：100+ 集成、webhook、审批步，替换等于重新接线并重新验证。
  • 已发布 app 有终端用户（App Users / GenesisAuth）：客户在用的门户，是最硬的留存——你不是在换工具，是在换客户的入口。

裂变 / 网络效应

有，而且做了三层：克隆即用（Free 可克隆 1,000+ free app kits，每次克隆占 Free 的 3 个 app 额度）、克隆给 credits（Earn Credits When Others Clone）、已发布 app 自带发现层（robots/sitemap/llms.txt）与公共 agent 页 + 5 种 widget 嵌入。「用额度做货币、用克隆做传播、用成品做商品」——这条闭环比单纯免费档更狠 [推断]。

04

产品架构 & 交互体系

界面 + 实体

核心产品界面（Surfaces）

Projects（数据层 = Memory）
结构化数据：任务树 + 自定义字段 + 10 种视图（List / Board / Table / Mind Map / Docs / Calendar / Gantt / Actionsheet / Org Chart 等）。注意 2026 版站点里「笔记 / 思维导图」已经不是独立对象，而是 project 的两种视图——这是理解它架构的关键。
AI Agents（智能层 = Intelligence）
一个有角色的 AI 队友：指令 + 知识（文件/项目/网页/YouTube/云盘）+ 持久记忆 + 工具（研究/文档/AI 步骤/工作区操作/外部 app/自定义）+ slash 命令。工具可各自设「自动执行」或「需人工批准」；多 agent 可组 AI Teams（Auto / Everyone / Manual / Orchestrate 四种模式）。
Automations（执行层 = Execution）
触发器 + 动作 + 控制流（Branch / Loop / Filter / Delay / Approval）+ 173 个连接器（6 类）。触发有四类：Taskade 内部事件、外部 app 事件、时间、入站（Webhook / Mailhook / Form）；动作可返回结构化 JSON 供后续步骤取字段。
Genesis App（界面层 = Interface）
一句话生成的 React app，由 Taskade 托管，读写上面三层；可发布到 *.taskade.app 或自有域名（含 SSL）、可 iframe 嵌入、可密码保护，并自带 App Users / GenesisAuth（独立于 Taskade 账号的终端用户登录）。这一层是它区别于所有「模板 + agent」产品的关键。
App Factory / App Kits（分发层）
6,135 个社区 app 页 + 72 个分类（48 类型 + 12 团队 + 12 行业）+ 495 个作者页；App Kit 可克隆、可免费/付费分发、可导出 .tsk、可导出 GitHub。它把「成品」变成了可流通资产——这是模板生意的下一层。
机器入口（MCP / SKILL.md / llms.txt）
给 AI 用的门面：Hosted MCP（https://www.taskade.com/mcp，OAuth 2.0 + PKCE）让外部 agent 读写工作区，SKILL.md 教它怎么用，llms.txt 连「该怎么引用我」都写好了。大多数产品把 AI 当用户，它把 AI 也当客户。

核心实体 · 整个系统绕着什么转

Workspace（顶层隔离单元：每个 workspace 有自己的 memory / intelligence / execution） Project / Task / Field（数据、行、列） View（同一份数据的 10 种看法） Agent（指令 + 知识 + 持久记忆 + 工具） Automation / App Kit（流程与可流通的成品）

信息架构逻辑

主轴是「项目」：一切从 Projects 进来，向上长成 Agent 的知识与记忆，向外长成 Automation 的触发与动作，最后被 Genesis App 包成界面。好处是四种封装共享同一份数据——改一处，四种入口都变；代价是概念密度极高：一个用户要同时理解 project、view、field、agent、tool、knowledge、memory、trigger、action、app kit 十个对象，才能完整发挥它。这也是它和 Notion 一类的分野：Notion 只要求你理解 block。

导航 & 交互模型

导航按「做什么」切：Create（Genesis）/ Projects / Agents / Automate / Apps / Templates / Integrations / Pricing / Learn / Docs。值得注意的是 /use-cases 与 /solutions 在 2026 版站点是 404——场景全部由 /apps/categories 的 72 类 app kits 与 /learn/projects/for-* 人群页承载。本期未实测，交互结论只据站点结构与文档，不下体验判断。

05

设计语言 & 手艺细节

「品味」到底体现在哪

它的所有工艺都指向一句话：把「一次性交付」变成「可流通的资产」。模板可复制、app 可克隆、记忆可 fork、每个产物自带发现层——资产能自己流通，产品就不需要靠投放获客。

01
把 AI 的记忆做成一个能编辑的 Project
这是全站最值得抄的一处：持久记忆不是藏在模型里，而是落成一个 Project，可浏览、可编辑、可搜索、可 fork。结果有三：用户能看见 agent「记住了什么」，能改错，能把记忆复制给另一个 agent；同时记忆顺带变成了产品里的数据资产。
02
TSK 阶梯：按任务档位选模型，而不是按厂商型号
TSK-Auto / Instant / Standard / Thinking / Reasoning 五档，用户选的是「这活有多难」，不是「用哪个模型」；Pro 起可 BYOK（OpenAI / Anthropic / Google，Business 再加 xAI / DeepSeek / Mistral / OpenRouter）。模型是耗材，产品是「任务到模型的路由」——这是 2026 年 AI 产品该有的抽象，因为模型半年换一代，而用户的心智不该跟着换。
03
三种封装：模板给结构、App Kit 给成品、MCP 给机器
Template 是「改一改就能用」的结构（3,997 项目模板 / 3,169 agent / 2,361 自动化配方）；App Kit 是「拿走就能跑」的成品（6,135 个，可克隆可售卖可导出 .tsk / GitHub）；MCP + SKILL.md 是「让别的 agent 直接调用」的接口。同一份对象图，三种交付粒度，三种买家。
04
用额度当货币，把增长写进计费规则
Free 档没有月度 credits，只能靠邀请与被克隆赚；克隆别人的 app 又会占用 Free 的 3 个 app 额度。于是「拉新」和「被复制」不再是运营活动，而是用户拿到额度的唯一路径。这是把增长动机直接焊进账本，比「邀请送积分」硬得多，也解释了它为什么敢把免费档做小。
05
让用户的产出自动带 SEO / GEO
官方 Publish 说明：每个已发布的 app 自动产出 robots.txt、sitemap.xml、llms.txt；Business+ 还带 SEO Health 评分与 app analytics。也就是说用户每发布一个 app，就替它多开一个搜索与 AI 发现节点——UGC 直接变成分发资产，这是它 21.4% 页面来自 UGC 的机制原因。

商业模式 & 变现

怎么赚钱
收入模型
订阅 + credits 双轨（额度既是成本也是拉新货币）

Free $0（2 成员 / 3 app / 1 agent / 10 次自动化/月 / 250MB / 1 知识源 / 无月度 credits）；Starter $6（10K credits、350 runs、3 agent、5GB）；Pro $10 年付、$20 月付（50K credits、1,000 runs、无限 agent、10 个自定义域名、webhook、.tsk 与 GitHub 导出、BYOK）；Business $25（150K credits、10,000 runs、无限成员与域名、白标与 SEO、SAML）；Max $100（400K credits）；Enterprise $250（1.1M credits、SCIM）。年付对 Pro 及以上省 50%。

免费 ↔ 付费 分水岭
免费停在哪

免费：2 成员、3 个 Live app、1 个自定义 agent、10 次自动化/月、250MB、1 个知识源、7 天版本历史、无自定义域名与 webhook、无月度 credits。付费：Starter $6 给 10K credits 与 Hosted MCP；Pro $10 给 50K credits、无限 agent、10 个域名、webhook、.tsk / GitHub 导出与 BYOK；Business $25 给 150K credits、无限成员与域名、白标与 SEO、SAML、TSK-Reasoning；Max $100 给 400K credits；Enterprise $250 给 1.1M credits 与 SCIM。

变现入口
入口小得反常，钱收在 credits 与「能对外发布」上

Free 档只给 2 个成员、3 个 app、1 个 agent、10 次自动化——小到像刻意设的墙：刚好够跑通一个真实场景，不够跑第二个。付费的三次跳：额度与 webhook（Starter/Pro）→ 对外品牌与域名（Business 起无限域名 + 白标 + SEO）→ 企业身份（Enterprise 的 SAML + SCIM）。它卖的不是功能，是「你能对外交付多少」与「你能跑多少 AI」。

体验 ↔ 变现 是否同向
体验与变现是对齐的，还是打架的？

结构上高度对齐，且对齐得很聪明：免费档把「跑通一个场景」的成本降到零，付费墙则立在「你开始对外交付」这一刻——更多成员（客户要登录）、更多 app（一个客户一个门户）、自有域名与白标（要给别人看）、更多自动化（流程开始依赖它）。这条线切得比多数 SaaS 准，因为它对应的是「业务真的在用」而不是「用户想不想升级」。打架的地方只有一处：credits 与 automation runs 是两种货币，用户很难预估「我这个月会不会超」，而超额的后果比功能受限更焦虑。

增长策略

明牌或推断

主要获取渠道

  • 程序化 SEO 矩阵：28,602 条 URL，其中 18,376 条是 templates / agents / automate / prompts / convert / generate 六类资源页（64.2%）；另有 197 条对比页（155 条 free-竞品-alternative）纯吃「免费替代品」搜索。
  • UGC 克隆工厂：6,135 个社区 app 页 + 495 个作者页进 sitemap，克隆给 credits、售卖抽成、已发布 app 自动带发现层——用户的产出就是它的内容资产。
  • AI 原生发现层（GEO）：llms.txt（含 How to Cite Taskade）+ SKILL.md + Hosted MCP + .well-known 元数据 + Accept: text/markdown + OpenAPI + TSK-Bench，robots.txt 明确 ai-train=yes / search=yes / ai-input=yes。它把「被 AI 引用」当成一条正式渠道在做。

主要增长循环

  • 额度货币环 — Free 档没有月度 credits，只能靠邀请（Earn AI Credits by Inviting Friends）与被克隆（Earn Credits When Others Clone）赚。于是「拉人」与「被复制」成了用户获得额度的唯一方式——这是把增长动作直接写进计费规则，比「邀请得积分」更硬。
  • 程序化 SEO + GEO 环 — 模板/agent/配方/提示词/生成器五套程序化页承接各种长尾搜索 → 落地页给 Free 档 → 用户克隆成品后自己发布 app → 新 app 自动带 robots/sitemap/llms.txt，成为新的发现节点。前两条是它写的，第三条是用户替它写的。

扩张向量

横向
  • 从任务到 app：Genesis 把「管理一件事」升级成「交付一个系统」——同一份数据，多了一层界面。
  • 从自用到售卖：App Kit 让成品可克隆、可定价、可导出，把用户变成渠道（[推断] 这是它唯一能绕开「模板同质化」的方向）。
纵向
  • 72 类 app kits：48 类型（CRM、客户门户、仪表盘、发票、预约、追踪器、知识库、聊天机器人、落地页、店铺、表单、计算器…）+ 12 团队 + 12 行业。
  • 代理机构与客户交付（Business 档就叫 For agencies and client work）：一个客户一个 app，白标 + 自有域名 + 终端用户登录。
平台
  • 开放接口齐全：Hosted MCP（OAuth 2.0 + PKCE）、REST v1 GA、Action v2 Beta、webhook / mailhook、OpenAPI JSON（v1/v2）、.well-known 元数据、GitHub 上的 mcp / skills / cli / awesome-vibe-coding。
  • [推断] 它的平台策略是「两端都做」：一边让别的 agent 通过 MCP 读写它（它当工具），一边把用户的 app 发布成独立站点（它当宿主）。这个双面位置比 Slack 的双向 MCP 更激进——因为它的 app 可以不挂在 taskade.com 域名下。

应用层六维

模型用得好不好

六维是本系列的主框架：前三条看值不值，后三条看敢不敢用、会不会留下。

本片判为 **原生**。拔电测试：拿走 AI，产品消失 → AI 原生。（依据：人工名单）

① 替掉哪一步

替掉的是「找人做一个小系统」这一段：原来要买一套 SaaS 或找开发（周级），现在一句话生成 + 模板改（分钟到小时级）。成本从「开发与采购」变成「订阅 + credits」（$0 起）。这是它最锋利的地方，也是它最容易被打断的地方——因为上游模型一旦直接产出 app，这段差价就没了。

② 脏活谁干

它啃掉数据存储、视图、判断（agent）、执行（automation）与界面（Genesis）五件事；甩回的是「设计判断」：一句话能生成 app，但业务该怎么跑、字段该怎么设、谁能看什么，仍然要人定。它把工程的活接走了，把产品的活留下了。

③ 出来能不能用

能用，但要人改一轮：App Kit 是「改一改」的起点，不是终稿；生成的 app 在真实业务里通常要调字段、权限与流程。本期未实测，此判断只据官方文档与 App Kit 的配方结构（如 Invoice Generator Pro = 3 projects + 1 agent + 3 automations）。

④ 错了怎么兜

兜底设计得比同类好：agent 工具可设「需人工批准」，自动化有 Approval step，EVE 会请求批准；但「一句话生成的 app」本身没有公开的失败率或回滚说明——这一层兜底仍是空白。

⑤ 错一次多贵

大体可逆：.tsk 导出、GitHub 导出、版本历史（Free 7 天 / Pro 1 年 / Business 5 年）都给了退路。不可逆的是「把客户拉进你的 app」：一旦客户在门户里提交了数据，换工具就等于迁客户。

⑥ 不用它的替代

个人换得掉（Notion 模板 + Zapier 能拼出七八成），团队换不掉：数据、agent 记忆、自动化接线、已发布 app 的终端用户，四样都在它这里。所以它的留存来自「资产在这里」，而不是「功能更好」。

他们真正在优化什么指标

[推断] 北极星 + 护栏

官方只公开三个累计量（150,000+ Genesis apps built、500K+ AI agents deployed、3M+ automation executions）与 sitemap 规模。以下分两类：可核实的公开事实，与标注 [推断] 的「它应该看什么」——后者不是真实数据。

北极星
每周被真实业务使用（不是被创建）的 live app 数（[推断]）

[推断] 它的收入按 credits 与 app 数量分档，但价值只在「app 真的有人用」时成立。「已建 app 数」会被一句话生成灌水（官方那个 150,000+ 就是这类口径），所以真正的北美星必须是「周活跃的已发布 app」。

输入指标 · 1
克隆 → 发布 → 有终端用户的转化漏斗

它的增长全押在「克隆即用」上（Free 可克隆 1,000+ free kits）。但克隆不等于使用：真正决定收入的是「克隆后有没有发布」与「发布后有没有 App User 登录」——这两个动作才叫「业务在用」。

输入指标 · 2
Automation 的周执行次数与失败率

自动化是它从「工具」变「流程」的分界线。执行次数决定黏性，失败率决定信任——一条每天跑失败一次的催款 flow，比没有这条 flow 更快让客户流失。

输入指标 · 3
App Kit 付费克隆的作者数与其收入分布

如果「创作者能靠 App Kit 赚钱」成立，它就从一个 SaaS 变成一个市场（marketplace 的网络效应比功能更强）。这条指标看的是创作者侧的收入集中度：只有少数人赚到钱，说明市场还没形成。

护栏指标
AI credits 的实际成本覆盖率 + 免费档用户的 credits 消耗

Free 档没有月度 credits，但用户在 Free 上克隆、建 app、调 agent 时依然在消耗它的推理与托管成本。免费越受欢迎，成本越先爆——这条护栏不设，增长会先把毛利吃光。

盲区
没有公开的留存曲线、付费转化率，以及 6,135 个社区 app 的活跃分布 [推断]

[推断] 程序化 SEO 的规模可以数（28,602），但流量不能从 sitemap 推出来——本期未取 Similarweb / Ahrefs 类数据。另一个盲区是 GEO 的效果：llms.txt 与 SKILL.md 有没有真的让 AI 推荐它，本身没有公开的度量方式，所以这一层目前只能算「做对了动作」，不能算「拿到了结果」。

credits 成本与免费档消耗的错配BusinessMediumMedium给免费档设一道真正的成本护栏（不是额度护栏）：限制并发的 agent 调用、把重任务排队、对 BYOK 用户降 credits 消耗。免费越受欢迎，这一条越关键。

终局判断

综合判定
为什么它赢

四层共享一份对象图、把 agent 记忆做成可编辑的 Project、6,135 个可克隆的 App Kit、28,602 页的程序化 SEO + UGC + 一整套 GEO 接口（llms.txt / SKILL.md / MCP / .well-known）、以及「用额度当货币」的增长机制。

在哪里断裂

需要强协作与治理的大企业（成员上限、权限颗粒度、合规都不够）；只想管项目、不想要 AI 的团队（credits 计价是噪音）；要复杂数据关系的业务（关系型建模不如 Airtable）；要高度定制界面的产品（Genesis 的自由度不如 Bubble）。

长期护城河

护城河是「中」：强在四层同构与分发规模（28,602 页 + 6,135 个 UGC app + 完整的 GEO 层），弱在每一层都能被更专注的对手单点击穿（数据模型不如 Airtable、自动化连接器不如 Zapier、界面不如 Bubble、品牌不如 Notion）。它真正的资产是那条 Living Loop 与创作者侧的资产市场——如果 App Kit 真能让人赚到钱，它就从「工具」变成「市场」，那是唯一别人抄不快的部分。

谁抢同一个需求抢同一段链路用户实际迁移
Notion同一个需求：想要一个「什么都能放」的工作区的小团队与创作者数据与文档这一段（Notion 是 block 模型，Taskade 是 project/task/field 模型）它给 Notion 备了 free-notion-alternative 页，另一头又有 30+ 导入器直接从 Notion 搬数据——两头都在打

Zapier / Make已经有工具、只需要把工具连起来的人自动化这一段（触发-动作编排）它的 automate（2,361 页）+ integrations（180 页）正对着打；但 Zapier 不持有数据层，这是它的机会
Softr / Bubble / Glide要「把数据做成一个能给客户用的界面」的人界面这一段——这是 Genesis 最直接的对手这一格它最难赢：对方的界面自由度更高，而它靠「数据+agent+自动化一体」来换
Airtable要强结构化数据与视图的团队数据模型这一段复杂业务会被 Airtable 挡住；Taskade 用「流程 + agent」而不是「字段能力」来避战
通用 AI agent（ChatGPT / Claude 等）所有想「说一句话就把活干了」的人智能这一段，且不持界面的包袱最不确定的一路：如果用户直接跟 agent 说话，中间那层工作区就多余了

读法：它在地图上的位置很独特——不在「项目管理」的正中央，而在「协作工具 × 自动化 × app builder」的三角中段。好处是几乎没有同构的对手；坏处是每一格都有一个更专注的强者，用户随时可以说「我为什么不直接用 Zapier + Bubble」。竞品价格本次全部未核验，不做价格对比。

竞品技术底座

附录 A

AI 构建过程（Taskade 怎么把原子拼成工作流）：① 四层——Memory（Projects 存数据）/ Intelligence（Agents 做判断）/ Execution（Automations 跨 100+ 集成执行）/ Interface（Genesis App 当界面）；② 一条环——Living Loop：Memory 给上下文 → Intelligence 做决定 → Execution 出结果 → 结果回流成新的 Memory；③ 八个基元——Project/Task/Field、View、AI Agent、Agent Tool/Skill、Knowledge Source、Automation Trigger/Action、Genesis App、App Kit；④ 一条公式——数据 × 智能（指令 + 知识 + 工具 + 记忆）× 执行 × 界面 = 一个 Living App。所以它的 AI 不是「加了一个助手」，而是把工作区按四层重写、再让 AI 长在每一层上。下表先摊开它自己的装配线，再看各家的底座锁住了什么。

产品底座它锁住了什么能力
Taskade一份对象图（Project/Task/Field）+ 四层封装（Projects / Agents / Automations / Genesis App）+ 模型路由（TSK 阶梯，可 BYOK）+ 托管与发布（自有域名、App Users）锁住「从数据到可交付界面」这一整条：别人卖其中一段，它把四段焊在一起
Notionblock 模型（页面即数据）+ 数据库视图 + 模板生态锁住「知识 + 文档」的心智与模板分发；自动化与执行是外挂
Airtable关系型 base + view + automation锁住「结构化数据建模」这一段：字段类型与关联能力是它的护城河
Zapier / Make触发-动作编排引擎 + 海量连接器锁住「系统之间的胶水」：连接器数量本身就是壁垒，但它不存数据、不做界面
Softr / Bubble / Glideno-code 界面构建器 + 外部数据源锁住「界面自由度」：能把界面做到像定制软件，但数据与 AI 要外接

[推断] 真护城河不在「一句话生成」，在「生成之后的那三件事」：数据存在哪、权限怎么给、产物怎么分发。因为生成能力是模型给的，任何人都能调；而 App Users（终端用户体系）、自有域名与 SSL、App Kit 的可克隆/可售卖/可导出，是产品自己搭的工程。Taskade 把这三件放在付费墙上（Business 起白标与 SEO、Enterprise 起 SCIM），说明它也知道钱在哪。
它最脆的一层是「生成」本身：一旦上游模型自己做到「一句话建 app 并托管」，它的入口价值就被抽走。所以它急着做 MCP + SKILL.md + llms.txt——不是因为时髦，是因为要确保即使 AI 变成入口，自己仍是那个被调用的执行层。

可迁移的机会（我的判断）

附录 A
  1. 把 「Living Loop」抄成记忆产品的默认结构——记忆落成用户可浏览、可编辑、可搜索、可 fork 的一张表，每次产出自动写回。为什么值得抄：这是它全套架构里最可迁移、也最容易被忽略的一招；大多数 AI 产品的记忆是黑盒，用户既看不见也改不了。最轻，改的是存储形态不是模型。
  2. GEO 不是写文章，是把机器可读接口做全——最低配三件套：llms.txt（事实 + FAQ + 该怎么引用我）、SKILL.md（给 agent 的操作手册）、一个 MCP 入口；进阶再加 .well-known、Accept: text/markdown、OpenAPI。为什么：它证明这套能做成标准动作，而多数团队还停在「写一篇讲 AI 的博客」。最快见效，一周能上。
  3. 把「额度」当拉新货币——邀请与被克隆给 credits，是新用户拿到额度的唯一路径，等于把增长动机焊进账本。但要给「我只想用基础功能」的用户一条干净的路（纯席位价），别让两种用户共用一套计价。
  4. 让用户的产出自动带发现层——每个已发布作品自动产出 robots/sitemap/llms.txt。做任何「用户作品」类产品，这一层应该默认打开：UGC 直接变成搜索与 AI 发现节点。最难被抄，因为它要求你的产品先有「已发布的作品」。

四个里哪个最该先做？第 2 个：它不依赖产品改造，只依赖把「给机器看的那一页」写对。哪个最容易被忽略？第 1 个——大家都把记忆当技术问题，其实它是产品问题：用户能不能看见、能不能改。

流量与变现拆解

附录 A

先把规模摊开（官方 sitemap 实测，2026-11-26，17 个子 sitemap 合计 28,602 条 URL）。结构比总量更重要：程序化资源页 18,376 页 = 64.2%（templates 3,997 / generate 4,526 / agents 3,169 / automate 2,361 / prompts 2,205 / convert 2,118）、UGC app 页 6,135 页 = 21.4%（community apps + 495 个作者页）、手写营销内容只占 14.3%（blog 1,125 / marketing 867 / wiki 573 / learn 435 / docs 169 / compare 197 / integrations 180 / ai 43 等）。再叠一层别人没有的：GEO 发现层——llms.txt（含 How to Cite Taskade 的指定引用措辞）+ SKILL.md + Hosted MCP + .well-known 元数据 + Accept: text/markdown + OpenAPI + TSK-Bench，robots.txt 明确 ai-train=yes / search=yes / ai-input=yes。

环节它怎么做的为什么有效 / 哪里漏
拉新程序化资源页 18,376 条 + 197 条对比页（155 条 free-竞品-alternative）+ UGC 6,135 条 + GEO 层有效：搜索意图覆盖极全，「免费替代品」这种高转化词都有页接。漏点：sitemap 只证明页面规模，不证明流量；本期未取 Similarweb/Ahrefs
激活克隆即用（Free 可克隆 1,000+ free kits）+ 一句话建 app + 模板改一改有效：新人一上手就在用「别人的成品」，不是空工作区。漏点：克隆占 Free 的 3 个 app 额度，第二次克隆就撞墙
留存数据 + agent 记忆 + 自动化接线 + 已发布 app 的终端用户（App Users）有效：四层都在它这里，迁走等于重建业务。漏点：留存的前提是「真的跑起来了」，而 6,135 个社区 app 的活跃分布未核验
变现订阅 + credits：Free $0 / Starter $6 / Pro $10（月付 $20）/ Business $25 / Max $100 / Enterprise $250有效：付费墙立在「开始对外交付」那一刻（更多成员、更多 app、自有域名、白标）。漏点：credits 与 runs 两种货币，预算算不清
扩张成员数 × app 数 × credits 三轴同时扩张；Business 起无限成员与域名；Enterprise 加 SCIM[推断] 扩张最顺的一轴是「代理机构」：一个客户一个 app，天然推动 app 数与域名数同时上涨

套利三问。钱从谁的兜里出：小企业主与代理机构的经营预算（不是 IT 预算），所以它用信用卡可付的 $6–$25 档做主力，而不是先攻企业。还能拿多久：[推断] 「程序化 SEO + UGC + GEO」这三层的组合窗口还有 1–2 年；一旦所有人都做 llms.txt，这一层的相对优势会归零。凭什么你拿到：凭它把「生成 → 托管 → 权限 → 分发」四段焊在一起，而这四段的工程难度递增——生成最容易，托管与权限最难。

最脆的那根梁：「一句话生成」这个入口。它既是它最响的卖点，也是最容易被上游吃掉的一层。真正的护城河在入口之后——已发布 app 的终端用户、可售卖的 App Kit、以及每个 app 自带的发现层。如果它继续把营销重心放在「一句话」，就会一直站在最容易被替代的位置上；如果重心移到「成品资产」，它才站得住。
