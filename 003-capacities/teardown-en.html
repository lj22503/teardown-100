01

Product Snapshot

What it really is

Beyond the marketing description — what this product actually is as a system.

The site calls it “The studio for your mind — a place for all your information”. In the product that means notes are not files: they are objects with a type, properties and a place. Upload a PDF and it lands with the other PDFs; add a meeting and it already knows about dates and attendees.

Core user promise

The why page promises three things: structure is built in, every day gets a page as your inbox, and every link is bidirectional. In plain words: usable today, no system design required.

Category & positioning

One counter-intuitive fact: neither the homepage, the pricing page nor whats-next files it under AI tools — whats-next actually says “AI in Capacities should stay assistive”. Yet the paywall sits precisely on AI: free has no AI assistant, Pro does. So its real position is: take Notion and Obsidian's installed base by removing setup cost, then monetise a second time through AI credits.

  • App Store figures come from the iTunes lookup endpoint (verified 11 Nov 2026: 4.2845 average, 116 ratings, version 1.72.13); the 40 reviews come from the iTunes review RSS feed, not an official chart

Target Users & Jobs-to-be-Done

Who + why

Primary user segments

  • Knowledge workers on their third or fourth note app — The migration chain in the reviews is explicit: Evernote → Notion → Roam → Obsidian → Capacities. These users are not short of tools; they ran out of patience for building systems. Hands-on: five obvious surfaces — books, projects, people, daily notes, ideas — and you know what to do immediately.
  • Researchers, writers and lifelong learners (mostly solo) — The comparison pages list Best For: researchers / writers / lifelong learners, which in the product means reading notes, meetings, projects and contacts. Hands-on: typing the book title Deep Work auto-filled the structured metadata — no manual entry.
  • Solo users who want clean context to feed an AI — Pro includes AI Chat Connectors (ChatGPT / Claude / Cursor can create and edit objects directly) and a REST API 2.0. The hands-on conclusion was that the field design itself is worth copying as a structured sample for a personal agent. Note that this segment has to be able to pay: free gets no AI.

Trigger & context

Trigger moment: Two moments: after migrating notes from one app to another yet again; or on starting to use AI and realising the notes vault cannot be fed to a model at all

Frequency: Capture and review are daily (the daily note); the object graph accumulates passively

Context: Reading notes, meeting notes, project tracking, contact management, idea fragments, a context library for an AI

Jobs-to-be-Done

Acquisition loop

Channel mix is not disclosed. Three verifiable channels: (1) six comparison pages harvesting long-tail search intent such as capacities vs obsidian / evernote / notion, which sit closest to purchase; (2) the why page speaking directly to Notion and Obsidian users about wasted database-building; (3) three Product Hunt launches holding a 4.8 rating.

Activation · Aha moment

The company bets on the aha of a PDF filing itself with the other PDFs. The aha that actually fired in testing was different: type a book title and the fields fill themselves — the first time no manual structured data was needed.

Retention drivers

  • The object graph thickens over time: open one person and every related context is there, so switching tools means abandoning the network
  • The daily-note habit is its steadiest retention driver (reviews repeatedly describe brain-dumping first and organising later)
  • Import and export to Markdown and CSV are included on all three tiers (pricing page), so lock-in is habit and graph, not data captivity

Virality / network effects

Weak but shaped: view-only sharing is on the free tier, so sharing is a natural outlet; what actually travels is screenshots of someone's object page. There is no referral programme.

Core entities · what the system is built around

Object (anything with a type) Object type (custom type plus properties) Daily note (one page per day) Space Collection / query

IA logic

There are no folders and no database for you to design. Layer one is what kind of thing this is; layer two is which properties it has; layer three is what it links to. All three are pre-built and the user only fills them in — the fundamental difference from Notion (design your own database) and Obsidian (design your own folders).

Navigation & interaction model

Two gestures cover the main path: @ to reference an object, / to insert a block. Learn those and the product is open; fail to learn them and you are still not stuck, because onboarding sits inside signup. Hands-on: there was never a moment of wondering where to click next.

05

Design Language & Craft Signals

What craft actually means

Every craft decision points at one thing: reverse the order of configure-then-use. You get a working structure first, and configuration becomes a by-product of using it.

01
Object types with inherited properties
Define a type once and every object of that type shares its properties; add a field to the type and existing objects get it too. This is the core move against Notion, where every database needs its own design
02
Backlinks on by default
No plugin, no query to write: mention something and a link appears under it. The comparison page puts it plainly — Backlinks by default, no query to write
03
The daily note as inbox
It removes the where-should-this-go decision from the entry point: today's writing lands on today's page and is promoted to an object later. WhatsApp, Telegram and email can all feed it
04
Pre-seeded examples and in-flow onboarding
Every type ships with default examples and the docs teach inside the product. Hands-on: instructions were embedded in the signup flow, which is why the first note took one minute
05
Everything built in, no plugins
Whiteboards, queries, calendar, tasks and AI are all first-party (whats-not-next states plugins are not planned). The cost is that long-tail needs are nobody's job; the gain is consistency and speed

Business Model & Monetization

How it makes money
Revenue model
Free core + Pro subscription + AI add-on (Plus)

Pricing page (Hong Kong region, captured Nov 2026): Basic free forever; Pro HK$77.99/month and Believer HK$98.99/month at monthly billing, with 16% off annually; Plus, an add-on at HK$66.67/month billed annually, buys a much larger AI budget with top-ups available. The official comparison pages use a single USD figure: Pro at $9.99/month billed annually. Believer differs by supporting the team and early access to new features, not by more capability.

Free ↔ Paid boundary
The boundary: intelligence and review

Free is structure plus storage: unlimited objects, spaces and custom types, sync everywhere, offline, import/export, view-only sharing, capture from WhatsApp / Telegram / email. Pro is retrieval plus review: AI assistant, smart queries, tasks, calendar integration, semantic search, version history, unlinked mentions, whiteboards, Readwise / Kindle import, public API, image and PDF analysis. (Source: the three-tier comparison on the pricing page.)

Monetization entry points
Give tidying away, charge for retrieval

Unlike peers that meter storage or object counts, it makes capacity unlimited — the thing users complain about most. Both paid layers only feel necessary after use: AI (let it read for me) and queries/calendar/tasks (let it schedule for me). The upside is that free users never run out of room to work; the downside is a gap between the AI note-taking pitch and the free experience.

UX ↔ Monetization alignment
Mostly aligned, with one structural tension

Aligned: the free tier does not cripple the core promise (structure, sync, export), and the thicker the graph the more reason to upgrade. Two tensions: (1) AI is the loudest claim yet sits entirely behind the paywall, so the first attempt always hits it; (2) the company states it will not build end-to-end encryption, and using AI shares data with model providers (docs) — a paying individual has to accept both at once.

Human ↔ AI task split

Where the product sits today on the AI-integration spectrum, and where the next 12–24 months push it.

Autonomous / Agentic

Current AI usage

All AI sits at Pro and above. Capability surface (docs): AI Chat inside Explore, a selection AI panel (translate / rewrite / summarise), auto-tagging, auto-collection, property auto-fill, image analysis including OCR and handwriting, /Ask AI, and AI-generated queries. The stated position is restrained: whats-next says AI should stay assistive, grounded in your notes and never in the way of your own thinking. Hands-on: the free tier genuinely has no AI, and the wall fires on AI and on tasks/Explore; without AI, data is not shared with model providers (docs), and that privacy notice was visible during testing.

What could become agentic in 12–24 months

  • Not shipped (my read): upgrade property auto-fill into proposing a whole object structure after reading messy material — today it fills existing fields, it does not propose structure
  • Not shipped (my read): let Connectors go from creating and editing a single object to restructuring a whole space in bulk (API 2.0 already provides the read foundation)
  • Not shipped (my read): a structure audit that flags objects missing the fields an AI needs. It is the one position that needs no model of its own, only its object model

Deeper AI opportunities

  • (my read) What it should build is not a stronger AI but a reusable asset: standard property sets for books, meetings, clients and projects. The hands-on reaction was that the structure itself is worth learning and feeding to one's own AI — users already treat it as a schema supplier; the company just has not productised it
  • (my read) Turn API 2.0 and Connectors into an agent's memory backend: agents write logs, conclusions and to-dos into the object layer and the human confirms. That is the only path from note app to infrastructure

Strategic AI-disruption risk

(my read) The threat is not a rival adding AI but a general-purpose agent growing its own object model. Once ChatGPT or Claude maintains your personal knowledge graph, nobody pays a second subscription for the shape of an object page — the cleaning layer it does for agents today is exactly what agents will do themselves

Opportunities & Redesign Ideas

Actionable PM thinking
Improvement · 1
Migration as a service
(my read) Its public weakness is type mismatch after import. A one-off migration plus type mapping — translating old Notion or Obsidian structures into its object types — is cheap to build, certain in demand, and aimed at people who have already shown willingness to pay tuition.
Improvement · 2
Field design as a reusable asset
(my read) Its object types are a ready-made schema: book, person, meeting, project. The hands-on reaction was immediate — this structure is worth learning and giving to an AI. The company treats it as an internal default and ships it undocumented; template packs and vertical editions (investment research, consulting, clinicians) are a revenue line that needs no new engineering.
Improvement · 3
A structure audit
(my read) Users do not know which objects an AI cannot read. A checklist of missing fields, missing links and missing context would move it from pretty notes to an agent-readable knowledge base — and it depends on the object model, not on model capability.
Strategic shift
From note app to the structured memory layer for agents
(my read) Its real differentiation is not AI but the cleaning it has already done: people, books, meetings and projects abstracted into typed objects with fields. The bet should be making that structure the default schema agents read and write (API 2.0 and Connectors are already there), not chasing model capability feature by feature.
🌙 Moonshot
Make its object spec the default structure of personal AI
(my read) If agents write contacts, books and projects using its fields, Capacities stops being an app and becomes the schema layer of personal AI — the analogy is not Notion but a database driver. A team of seven cannot build models, but it can build a standard; once adopted, the migration arrow points the other way.

Final PM Verdict

Synthesis
Why it wins

Structure out of the box and the object model: nothing to build, types on day one, first note in a minute

Where it breaks

Mobile (capture is broken) and migration (types do not match), plus the customisation ceiling

Long-term moat

The moat is the feeling that nobody wants someone else's system — not the technology. The object model is copyable; convincing users that this time they will not have to build anything is not. The same logic means it cannot stop general-purpose agents from eating the object layer from above.

Transferable opportunities

Appendix A

Three practices worth taking, none of which requires rewriting code:

Traffic and monetisation

Appendix A

/whats-not-next (live Nov 2026) publishes the refusals: tablet handwriting, formulas and advanced automation, flashcards and spaced repetition, RTL languages, collaboration and team plans (on hold), object inheritance, end-to-end encryption, lifetime subscriptions and plugins. The value of the list is that these are out of scope rather than pending — users need not wait.

The exit path: export supports Markdown and CSV on all three tiers (pricing page: Import and export to Markdown, CSV, and more — included on all), so leaving does not require permission; API 2.0 and the TypeScript SDK on Pro let objects be pulled out in bulk. Anyone returning to Obsidian gets Markdown; anyone moving to Notion gets tables.

My read: refusing E2EE and refusing plugins are two sides of one trade — both would slow down consistency and speed. That trade is sensible for personal, cloud, AI-assisted use; but it also means anyone who puts privacy first is destined for Anytype or Obsidian, and no amount of interface polish wins them back.
