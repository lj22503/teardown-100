01

产品快照

它到底是什么

抛开营销话术 — 把这个产品当成一个「系统」来看，它到底是什么。

Reflect 是一款以「每日笔记 + 双链」为骨架、极简到几乎不需要配置的笔记应用。2022 年在 Product Hunt 以云端端到端加密笔记走红，2026 年转向开源本地版 Reflect Open：MIT 协议、笔记就是你自己选的文件夹里的 Markdown、可选 AI 用你自己的 API key。

核心用户承诺

官方首屏原话：Think better with Reflect；Never miss a note, idea or connection。

品类 & 定位

在 PKM 货架上它站在 Obsidian 与系统备忘录之间：比 Obsidian 少一层 vault 与插件概念，比系统备忘录多一层双链与可问的 AI。[推断] 它真正的对手不是功能表上的任何一家，而是「用户决定这次不折腾」的那一瞬间。

前提假设

  • [推断] 用户规模：官网 2026-11 版无任何用户数字，PH 4.8 / 45 条是唯一可核实的社会证明；对照 Obsidian 552 万月活（第三方口径，见附录 17）差距明显，因此我不写任何用户量数字。
  • [推断] 转型空窗：官网只写 Reflect Classic 仍维护、Classic 付费用户赠一年 iOS 版；我按「新版重写 + 老版维护 + 两套同步方式（云端加密 / 本地文件）」推断它正处于转型期，而不是一个新品类扩张期。

目标用户 & Jobs-to-be-Done

谁 + 为什么

主要用户分层

  • 每日记录型知识工作者 — 记者、产品、咨询：会议笔记 + 日历 + 人脉 CRM 收在同一个地方，靠日期回忆而不是靠分类回忆。
  • 被 Notion / Obsidian 复杂度劝退的人 — 想要双链，但不想先学 vault、插件与配置。PH 原话：「thought I required a very heavy feature set」。
  • 隐私敏感的苹果用户 — Classic 是端到端加密，Open 是本地文件；两端都只面向 Mac 与 iPhone/iPad。

触发 & 场景

触发时刻： 会议开始前一分钟 / 读到一段想留的话 / 脑子里冒出一个要跟进的人

使用频次： 每日

使用场景： Mac 桌面为主 + iPhone 随手记。实测（燃冰）：官方签名分发只给 Mac（iOS 走 TestFlight），GitHub Releases 另附未签名的 Windows/Linux 构建，所以我的 Windows 主力机没走通——这是它对我最硬的一道门。

Jobs-to-be-Done · 用户「雇佣」这个产品去做什么

功能层
把当天发生的（会议、读到的、想到的）记进一个默认位置，之后靠时间与双链找回来，而不是周五晚上补分类。
"当 ___ 的时候，我想要 ___，这样我就能 ___。"
情感层
别再让我为一个笔记系统当项目经理——我不想在打开 App 之前先做一次架构决策。
"我想要感受到 ___ / 避免感受到 ___。"
社交层
在同事眼里是「笔记清爽、随时能调出上次会议结论」的人，而不是插件折腾党。
"我想要别人把我看成 ___。"

产品架构 & 交互体系

界面 + 实体

核心产品界面（Surfaces）

今天的日记
唯一默认入口，打开即写。
日历 / 时间轴
所有日期摊在一屏，负责跳转与回看。
图谱
看双链长成什么样，评论里被单独点名称赞。
搜索与问笔记
⌘K 搜笔记/反链/标签，⌘J 向笔记提问，答案回链到源笔记。
设置：同步 / API key / private 标记
把隐私与模型供应商的选择交回用户。
CLI（reflect today / search / show）
给脚本与 agent 用的入口，官方 README 里有 docs/cli.md。

核心实体 · 整个系统绕着什么转

Note（一个 Markdown 文件） Daily note（按日期的笔记，默认落地页） Person（由日历 / 联系人与 [[ ]] 带出来） Project / Topic（普通笔记，靠链接升格） Tag（# 标签，可被搜索索引）

信息架构逻辑

只有一条主轴：时间。所有内容挂在某一天下面，再靠 [[ ]] 横向连出去；没有文件夹、没有数据库、没有侧边栏树。这是它零配置的来源，也是它结构弱的来源——Obsidian 让你自己搭，Reflect 替你决定「只有时间轴」。

导航 & 交互模型

导航只有三个动作：上下翻日期、⌘K 搜、点反链跳。实测（燃冰）：确实不需要想「下一步干嘛」，但也找不到「按项目看全部」的入口。

AI · 未来就绪度

人 ↔ AI 任务分工

今天这个产品在 AI 整合光谱上的位置，以及未来 12–24 个月会被推向哪里。

Level 1
辅助 · Assistive
Level 2
嵌入 · Embedded
Level 3
自主 · Agentic

当前 AI 使用状况

AI 是可选辅助层，不在主循环里：官网原话 Optional AI，用你自己的 API key，可直连 OpenAI / Anthropic / Google / OpenRouter（GitHub README）；答案带源笔记链接，private: true 的笔记不进入 AI。实测（燃冰）：它内置了一批写死的提示词（会议要点、行动项、改写、摘要），价值在「提示词已经替你写好」，不在模型本身——所以我把它归为 assistive，不归 embedded。

12–24 个月内可 Agent 化的环节

  • 本地 .md + CLI：让 agent 直接吃 today / search / show 的输出，笔记变成 agent 的记忆盘
  • 会后自动整理：录音 → 转写 → 摘要 → 行动项，官方已把这条链路做成内置提示词
  • [推断] 「替我起草今天该写什么」：用双链历史做上下文，目前没做

更深层 AI 机会

  • 把「下一步写什么」做成默认动作：打开今天先给三行上下文建议（我的判断）
  • 把内置提示词做成成套能力（会议 / 面试 / 复盘各一套），现在只是一列清单（我的判断）

被 AI 颠覆的战略风险

最大的风险不是竞品，是品类被消解：如果 Cursor / Claude Code 这类工具直接读写本地 .md，「笔记 App」这层壳就不是必需品（这条判断与实测记录里的同向结论一致）。

可迁移的机会

附录 A

三条，都是我的判断，不是它的路线图：

（我的判断）一、把「打开就是今天」做成 agent 的默认记忆层。官方已有 CLI（reflect today / search / show）。把这三条命令的输出契约固定下来，让任何 agent 都能读今天、搜过去、取单篇，笔记就从「一个 App」变成「一层基础设施」。这是它唯一不跟 Obsidian 抢的地方。

（我的判断）二、给非苹果用户一个说清楚的入口。实测（燃冰）卡在没 Mac；但 Open 版的本质是「文件夹 + Markdown」，Web 加本地目录在 Windows 上完全能跑。缺的不是能力，是一句「Windows 支持到哪一步」的承诺。

（我的判断）三、把内置提示词做成成套能力。它现在内置一列写死的提示词（会议要点、行动项、改写、摘要），价值在「已经替你写好」。把这列变成会议 / 面试 / 复盘三套，再配一条「今天该写什么」的建议，AI 才从可选变成默认。
