# 豆包工作台拆解（19 个分享链接）

> 2026-11-27。用户给的 19 个豆包工作台分享链接（原话 21 个，其中 1 个重复）。
> 采集方式：ego-browser 带登录态访问 `doubao.com/workbench-share/<id>`（必须先访问 `/chat/` 再进分享页，否则拿到登录墙）。
> 本目录是 `_kb` 的一个**专题子库**：不并进 `01-products.csv`（那是按"产品"拆的），单独成表。

---

## 一、为什么单独建

`_kb` 的主表是「一个产品 = 一行」，字段是原子/工作流/渠道那一套。
豆包工作台不是产品，是**「技能 × 插件」的预设组合**——用同一套字段拆会串味。

所以这里用另一套最小字段：

| 字段 | 含义 |
|---|---|
| `id` | 分享链接里的 ID |
| `name` | 工作台名称 |
| `greet` | 入口问候语（决定了它默认让你干什么） |
| `desc` | 官方一句话定位 |
| `n_skills` / `n_plugins` | 技能数 / 插件数 |
| `skills` | 技能清单（`|` 分隔） |
| `plugins` | 插件清单（`|` 分隔） |

## 三、采集口径（复现用）

1. 先 `goto https://www.doubao.com/chat/`，等 4s（建立会话）
2. 再 `goto https://www.doubao.com/workbench-share/<id>`，等 5.5s
3. 取 `document.body.innerText`：
   - 第 1 行 = 工作台名
   - 含「？」且短的行 = 问候语
   - 最长的一行（>40 字）= 官方定位
   - 「包含技能与插件」之后到「去豆包打开工作台」之前 = 技能与插件清单
4. 插件靠关键词表识别（数据源/会议/SCRM 类），其余算技能

**踩坑**：直接开分享页会返回空白或「切换账号」；连续快速跳转也会被挡。必须"先回首页、再进分享页"，且每次之间留 3–5 秒。
