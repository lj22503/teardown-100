# 四个场景：怎么从这 20 个豆包工作台里拼出自己要的

> 2026-11-27。数据见 `workbenches.csv`（20 个：19 个批量采集 + 金融投研单独采集）。
> 一句话发现：**20 个里只有 5 个挂了插件，其余 15 个是「纯技能包」。**

---

## 〇、先看清这 20 个的分布

| 观察 | 数字 |
|---|---|
| 总数 | 20 |
| 挂插件的 | **5 个**（营销 23、金融投研 10、数据分析 2、法律事务 2、游戏制作 1） |
| 纯技能 | 15 个 |
| 平均技能数 | 22 |
| 技能最多的 | 医生工作台 **49**、营销工作台 25 |

**结论**：
- **挂插件的才是「能干活的」**，其余 15 个是「会写字的」——它们的技能是同义反复的提示词。
- 所以**做工作台的关键动作是：选一个骨架 → 挂对插件 → 加/删技能**，而不是从头写 50 个技能。

三个可直接抄的骨架：

| 骨架 | 为什么 |
|---|---|
| **金融投研工作台** | 离我们的活最近，10 个数据插件都是现成的 |
| **数据分析工作台** | 结构化思路最干净（数据 → 分析 → 图表 → 报告） |
| **产品项目工作台** | 「需求 → 拆解 → 跟进」的骨架，适合投顾的客户旅程 |

---

## 一、投顾工作台：以「金融投研工作台」为原型

### 为什么选它

它有 10 个数据插件（万得/同花顺/东财/晨星/盈米等），18 个技能已经覆盖「看市场、读财报、比产品」。这是最难自己造的部分。

### 要加什么（它缺的四件）

| 加什么 | 加在哪 | 具体 |
|---|---|---|
| **客户管理** | 资料库 + 技能 | 客户表（飞书多维表格或资料库快照）+ 三个技能：客户建档、跟进记录、下次联系提醒 |
| **陪伴素材** | 技能 + 插件 | 技能：素材改写、分层讲解（新手/老手/保守）、话术生成；插件：微信公众号 / 秀米（可选） |
| **持仓诊断** | 技能 + 插件 | 技能：四项诊断（集中度/重叠度/期限错配/成本）；插件：**盈米基金**（基金诊断）或晨星 |
| **接话** | 技能 | 33 条场景卡 → 压成 3 个技能：情绪接话、异议处理、波动应对 |

### 要删什么

| 删掉 | 为什么 |
|---|---|
| 一级市场公司评估 | 投顾用不上 |
| 衍生品研究、量化研究 | 散户客户几乎不涉及 |
| 多股对比、选股工具 | 投顾不选股，只做配置（留着会诱导顾问做不该做的事） |

### 最终配置（建议 12 个技能 + 8 个插件）

**技能**：个股研究、行业分析、公告解读、业绩分析、固收研究、基金 ETF 研究、估值建模 ＋ **客户建档**、**跟进记录**、**接话三件套（情绪/异议/波动）**、**持仓四项诊断**、**陪伴素材改写**

**插件**：豆包金融数据检索、Wind Alice、同花顺 iFinD、东方财富妙想、晨星、盈米基金、证券之星、腾讯会议

**入口问候语**改成：`今天要见谁？还是要看市场？`（原版是「今天想研究哪个市场、行业或标的？」——纯研究视角，投顾一半时间不在研究）

## 二、金融行业产品经理工作台：以「产品项目工作台 + 数据分析工作台」为原型

### 产品经理的活是什么

需求 → 调研 → 方案 → 评审 → 排期 → 上线 → 复盘；对内要说服，对外要合规。

### 从豆包现成的拿什么

| 拿哪个 | 拿什么 |
|---|---|
| **产品项目工作台** | 需求拆解、优先级、里程碑、评审材料 |
| **数据分析工作台** | 指标口径、漏斗、留存、A/B |
| **金融投研工作台** | 行业/公司/政策解读能力（做竞品与市场判断） |
| **法律事务工作台** | 合同/条款审查的思路（做合规评审材料时用） |

### 要加的插件

| 用途 | 插件 |
|---|---|
| 需求与文档 | 飞书（文档/多维表格）、腾讯会议 |
| 数据 | 豆包金融数据检索、聚源问数（业务口径） |
| 竞品与舆情 | 进门投研、凤凰财经 |
| 上线后看数 | 巨量/有赞类（若做 C 端）、数据分析工作台自带 |

### 12 个技能建议

需求拆解、竞品对比、用户访谈提纲、PRD 骨架、指标定义、漏斗分析、A/B 设计、合规评审清单、上线检查清单、复盘报告、路演/汇报材料、对外宣发稿

**一句话**：产品经理这个台**更依赖写作与结构化**，插件只要 3–4 个（飞书、金融数据、会议）。

## 三、一人公司工作台：覆盖你手上正在做的事

### 你现在在做的事（从这些天的活里归纳）

| # | 在做的事 | 对应现成工作台 |
|---|---|---|
| 1 | 投顾产品与资源站（MangoSource/顾问站） | 产品项目工作台 |
| 2 | 内容生产（拆解、笔记、公众号） | **写作工作台**、新媒体创作工作台 |
| 3 | 拆解与知识库（teardown-100、_kb） | 数据分析工作台（结构化） |
| 4 | 交付物（方案、一页纸、PPT、HTML 页） | 产品项目工作台 + 视频组装工作台 |
| 5 | 客户/学员/圈子运营 | 营销工作台（私域、活动） |
| 6 | 财务与发票 | **财务行政工作台** |
| 7 | 合同/协议/授权 | 法律事务工作台 |

### 一人公司的台该长什么样

**不要一个台，要两个台**：

| 台 | 干什么 | 原型 | 必需插件 |
|---|---|---|---|
| **生产台** | 拆解 → 写 → 出成品（文章/PPT/网页/一页纸） | 写作工作台 + 产品项目工作台 | 飞书（存稿）、剪映/创客贴（成品） |
| **经营台** | 客户/学员、社群、财务、合同 | 营销工作台 + 财务行政工作台 | 飞书（表）、企业微信、有赞/知识星球 |

**关键**：一人公司最缺的不是技能，是**「今天该干哪件」**——所以两个台的入口问候语都要写成"今天推进哪个？"而不是"想研究什么"。

## 四、两套工作台，并行不嵌

**WorkBuddy 和豆包是两套独立栈**：有人只用 WorkBuddy，有人只用豆包。**不要设计成"豆包查数据 + WorkBuddy 管客户"**——那等于逼用户装两个东西。

每一套都必须自己闭环。差别只在这几处：

| 五件事 | 豆包版怎么解 | WorkBuddy 版怎么解 |
|---|---|---|
| ① 客户管理 | 飞书多维表格（用豆包自带的飞书连接器） | **本地文件夹**（clients.csv / followups.csv） |
| ② 分享观点 | 内容技能 + 资料库素材 | 写作专家（文博凯）+ 本地素材库 |
| ③ 市场洞察 | ✅✅ **30+ 金融插件直连**（万得/同花顺/东财/晨星/盈米） | ⚠️ 腾讯自选股团 / 严研行 / 严估深（没有数据直连） |
| ④ 持仓诊断 | 盈米 / 晨星插件 + 会话贴持仓 | 理财财专家 + 本地四项诊断算法 |
| ⑤ 接问题 | 会话 + 资料库场景卡 | 专家 + 场景技能 |

### 两套的强弱正好互补

| | 豆包版 | WorkBuddy 版 |
|---|---|---|
| 数据能力 | **强**（直连 30+ 数据源） | 中（靠专家团与公开页面） |
| 数据私密 | 弱（云端 + 飞书） | **强（本地文件）** |
| 上手速度 | **快**（选台 + 挂插件，1 小时） | 中（配文件夹 + 挂专家，半天） |
| 手机可用 | **能** | 弱（桌面端） |
| 适合谁 | 客户问得多、要随时查数据 | 客户资料敏感、要留痕、要自主 |

### 怎么对外交付

| 用户说 | 给哪份 |
|---|---|
| 「我用豆包」 | `18-豆包版工作台-完整配置.md` |
| 「我用 WorkBuddy」 | `19-WorkBuddy版工作台-完整配置.md` |
| 「我两个都用」 | 先给一套跑通，另一套只当参考，**不要同时上** |

**一句话**：**一套做完再做另一套；不要混着搭。**

---

## 五、四条结论

1. **20 个台里只有 5 个挂插件**——「挂插件」才是工作台和提示词库的分水岭。
2. **投顾台**：豆包以金融投研为骨架；WorkBuddy 以理财财 + 周备全为骨架。
3. **两套并行**：豆包强在数据，WorkBuddy 强在私密与留痕；各自闭环，不互相嵌。
4. **一人公司**：拆「生产台 + 经营台」两个，入口问"今天推进哪个"，这条两个平台都适用。
