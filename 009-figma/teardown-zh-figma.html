Principal PM 判断

它是设计行业的默认工作台，护城河是「同事都在这儿」的协作网络与文件标准，不是 AI；而它现在最疼的地方不是能力，是席位账单、权限与账号安全。

作为「嵌入型」产品，拔掉 AI 它照常干活（实测结论：嵌入）——所以门槛不写在模型上，写在软件与生态上：组件、设计系统、开发交付、以及团队协作的默认路径。评论里的撕裂也很清楚：G2 4.7 分夸的是实时协作与易上手，负面反馈几乎全砸在「席位被自动升级」「重复收费不退」「Team Admin 改不了文件权限」「账号被关三年稿子没了」这四件事上，与设计能力无关。
5 / 5 · 战略强度
如果你只看三件事 —
  • AI 是后加的一层，不是产品本体 — 官网现在把 Figma Agent 与 MCP 摆在显眼位置，但实测（燃冰）走完一圈的结论是：它替掉的是找组件、摆版式的那段时间（我做一次页面花了 132 积分），不是判断。拿掉 AI，它还是那个设计工具——能画、能改、能交付。
  • 门槛在软件，不在模型 — 实测原话：它的门槛在于设计和原型编辑。这句和 007 Framer 正好互为镜像——一个的门槛在软件（设计判断），一个在软件（SEO 与托管），都不在模型。这也解释了它为什么敢把 AI 做成 credits 附加项：核心价值不靠它。
  • 最脆的梁是席位账单与权限 — Free 档封掉 inspector（Dev Mode），付费档按三类席位分别计价；G2 的负面反馈里有三条互相独立的投诉：外部协作者被系统自动升成 full member 并计费 14 个月、错误计费被承认却拒退款、Team Admin 拿不到文件的权限。这些都不是设计问题，是计费与权限模型的问题。

01

产品快照

它到底是什么

抛开营销话术 — 把这个产品当成一个「系统」来看，它到底是什么。

Figma 是一个跑在浏览器里的协作式界面设计平台：设计、原型、白板、幻灯片、开发交付、AI 生成与站点发布，都挂在同一套文件与权限模型上。

核心用户承诺

官方一句话（Product Hunt 产品页原文）：The collaborative interface design tool。翻成用户语言：一个链接发出去，设计师、产品、开发同时在同一个文件上说话，不用再导出、不用再对版本。

品类 & 定位

它站在两条货架的交叉口：设计工具（Sketch、Penpot）与「设计到上线」的建站工具（Framer、Webflow），再加上 AI 生成（Lovable、v0）。位置上它偏设计侧但更靠协作与交付：比设计工具多了 Dev Mode 与社区，比建站工具少了自主发布与 SEO 深度，比 AI 生成工具多了可维护的组件体系。

前提假设

  • [推断] 本次定价页返回的是美元原价、年付口径；第三方评测另称月付为 20 美元、单人档含无限文件与 Dev Mode——两套口径并存，本卡以官方页为准，其余只作量级参考。
  • [推断] 付费核心是「团队里有 1–3 个真正做设计的人 + 一堆只评论的人」：席位分三类、评论免费、编辑收费的结构，只在这种团队构成下才成立，也解释了为什么席位会误升级。

02

目标用户 & Jobs-to-be-Done

谁 + 为什么

主要用户分层

  • 产品设计团队与设计系统负责人 — 官网 Solutions 与客户案例都围绕团队协作展开；G2 好评原话集中在 collaboration、real-time collaboration、comments and dealing with the comments are very handy。他们要的不是更快出图，是「同一个文件里没有人拿错版本」。
  • 独立设计师与一人公司 — Professional 单人档 16 美元/月就能拿无限文件与 Dev Mode（第三方评测口径，本次未逐项核实），对一人公司是最低门槛的专业工具。实测（燃冰）就是这一层：一个人改自己产品的界面，不需要别人授权。
  • 开发与交付侧 — Dev seat 12 美元/月，Dev Mode 出代码与规格，把「标注—切图—沟通」这一段压掉。但评论里也有开发者直接抱怨 Free 档封掉 inspector（原话：Free version blocks inspector mode, now renamed to dev node）。

触发 & 场景

触发时刻： 手上有一个具体的、已经在用的页面，越看越不对——要改导航结构、要换卡片样式、要更像一个正经产品。实测（燃冰）的触发点就是这个，不是「我想学 Figma」。

使用频次： 项目期高频（改版、上新、评审循环），平时低频（维护组件与设计系统）。官方未披露使用频次数据。

使用场景： 浏览器为主，另有桌面端；协作发生在同一个文件里（多人光标、评论、分支）；交付侧走 Dev Mode 与 MCP；生成侧走 Make 与 Figma Agent。

Jobs-to-be-Done · 用户「雇佣」这个产品去做什么

功能层
把一个界面想法变成可评审、可交付的稿：能改到像素级、能点得动、能交给开发照着做。
"当 ___ 的时候，我想要 ___，这样我就能 ___。"
情感层
不想再被问「这是最新版吗」；也不想承认自己画的界面丑——实测（燃冰）的原话就是：我觉得我现在设计的太丑了，可能不符合用户的使用习惯。
"我想要感受到 ___ / 避免感受到 ___。"
社交层
在团队里显得专业：有组件库、有设计系统、有交付规范，而不是丢一堆截图。
"我想要别人把我看成 ___。"
03

核心产品循环

系统动力学

引擎 — 一次使用如何滚成留存，运气好还能滚成增长。

触发 · Trigger
这版看着不对
触发点不是「我要用 AI」，而是「这个界面不符合使用习惯」。实测（燃冰）的原话：这个是一个桌面投资工作台，我觉得我现在设计的太丑了……我希望调整成左侧抽屉，然后展示要符合金融卡片的样式。
→
行动 · Action
发页面、说要求、让它出一版
实测（燃冰）的做法：直接把线上那个不合适的页面发给它，用自然语言说清要什么（左侧抽屉式导航、金融卡片布局、红涨绿跌）。它的回应是给一版按原稿改的稿子，并附 node 链接。
→
奖赏 · Reward
拿到一版能直接改图层的稿
实测（燃冰）记录：它保留了奶油底色与芒果橙，也保留了未录入持仓状态、演示数据说明与免责声明——也就是说，它给的不是一张效果图，是一份可继续编辑的文件。
→
回访 · Return
下一次改版，组件已经在库里
第二轮的起点不是空白画布，而是上一次沉淀下来的组件与状态。这是它和「一次性生成」类工具最大的差别：资产留下来了，所以回来有复利。
"它真正教用户的是「把界面拆成组件与状态」的思维方式——一次做完，留下的不是这一版稿，是以后每一版都能用的零件。"

获取循环

入口有三条同时跑：Community 里的公开文件与插件（照着一个现成的改，比自己从零画快）、团队内一人带入后整组渗透、以及设计教育与作品集文化。第三条的反证在评论里：外部协作者被系统自动算成成员并计费——渗透太顺，所以账单会漏。

激活 · Aha 时刻

第一次看见同事的鼠标在同一个文件里移动、评论直接钉在图层上。这一下之后，「传文件—等回复—对版本」这套旧流程就回不去了。

留存驱动

  • 文件沉在账号里：稿子、组件、评论历史都在，迁移不是换工具，是搬家。
  • 组件库与设计系统一旦成规模，新项目绕不开它——复用比重建便宜。
  • 流程绑定：评审、交付、Dev Mode 都长在文件上，换工具等于改流程。

裂变 / 网络效应

有，而且写在定价页上：付费档可以让人查看与评论而不必再买席位（原文：If you're on a paid plan, you can let others view and comment on your files without purchasing extra seats）。分享链接即传播，收钱在后面——但这也正是席位误计费的来源。

04

产品架构 & 交互体系

界面 + 实体

核心产品界面（Surfaces）

画布（Canvas）
产品本体。中间是无限画布与 Frame，左边图层树，右边属性面板，顶上是工具栏与协作头像——设计对象在这里就是交付对象。
图层树与属性面板
对象模型的外显：Frame 套 Frame，组件与实例在树里可见，改父级还是改实例一眼能看出来。实测（燃冰）能直接用，靠的就是这一层——可以改图层。
Dev Mode
给开发的阅读模式：代码片段、规格标注、组件映射。它把「设计到代码」这一段从口头沟通变成可复制的东西；Free 档封掉的正是这里的 inspector。
Figma Make / Figma Agent
生成面：用自然语言描述出一版可编辑的界面或原型，按 credits 计量。实测（燃冰）一次页面 132 积分就是花在这一层。
Community 与插件
分发面：公开文件、设计系统、UI kit、图标与插件。它是拉新入口，也是「不用从零开始」的默认答案。
团队与权限（Team / Project / File）
钱与权都在这一层：席位类型、项目权限、文件所有者。G2 的负面反馈大半落在这里——Team Admin 改不动别人名下的文件，所有者一离职就成了孤儿文件。

核心实体 · 整个系统绕着什么转

File（一个设计文件，协作与权限的最小单位） Frame / Page（画布上的容器与页面） Component / Instance / Variant（组件、实例与变体） Seat（Full / Dev / Collab 三类席位，计费单位） Team / Project（团队与项目，权限与账单的边界）

信息架构逻辑

主轴是「文件」：进团队 → 进项目 → 进文件 → 进页面与图层。所有能力（原型、Dev Mode、Make、Sites）都挂在文件上，而不是另开一个产品壳。这个结构的代价是权限必须两级（团队级与文件级），而两级之间有一个洞：文件归个人所有，团队管理员未必能接管——评论里「所有者离职就丢文件」就是从这个洞掉下去的。

导航 & 交互模型

对设计师几乎零学习成本：左树、中画布、右属性，与 Sketch 时代一脉相承；对非设计师有词汇门槛（Frame、Auto layout、Component、Variant、Seat），实测（燃冰）没卡在界面上，卡在「怎么把想法说清楚」这一步。

05

设计语言 & 手艺细节

「品味」到底体现在哪

先让团队愿意在同一个文件里工作，再谈 AI 能生成多少。它所有 AI 都长在文件上，而不是另开一个聊天窗口——这决定了它的 AI 是「加速已有流程」，不是「替代流程」。

01
同一个文件，多人同时在场
实时协作不是功能清单里的一行，是产品的底层假设：光标、评论、分支、版本都在文件里。它把「对齐版本」这件事从流程里删掉了——这是它最难被替代的地方。
02
组件与变体：把设计做成系统
组件、实例、变体让「改一处、全站生效」成立。这一层决定了它的用户会越用越重：库越大，搬家的成本越高。
03
生成的仍是可编辑图层
实测（燃冰）最关键的一条：它的产出不是一张图，而是能继续改图层的稿，连未录入持仓状态、演示数据说明、免责声明这些细节都保留。生成类工具里，这一点仍然稀缺。
04
Dev Mode：把交付做成阅读模式
同一份文件切一个模式给开发看，代码与规格就近可得；再加 MCP，外部 agent 也能读进来。它卖的不是「设计更好看」，是「设计到代码少一次翻译」。
05
把 AI 做成 credits，而不是做成入口
AI 能力（Make、Agent、图像与本地化）挂在 credits 上，按席位附赠、超出加购。这是个克制的设计：不改变主路径，只给重度用户加一层计价——代价是重度用户会觉得每一次生成都在花钱（实测：一次页面 132 积分）。

产品的手感
价值到达速度
价值到达时间：本次未测（实测只记录「发一个页面进去、出来一版能用的稿」，未做计时）

用户挣扎风险
摩擦：席位误计费、权限归属、大文件性能

关键惊喜时刻

  • 生成之后还能改图层，连状态与免责声明都保留（实测原话：可以改图层）。
  • 分享链接就能评论，且不必为评论者买席位（定价页原文）——协作的门槛被压到很低。
  • Community 里的公开文件与设计系统可以直接抄改（G2 好评原话：thousands of open-source design systems, UI kits, wireframes, and icons），起手速度极快。

用户可能卡壳的地方

  • 席位计费会自己长出来：外部协作者被系统升成 full member 并计费 14 个月；同一文件多人却各自开账号导致重复收费，官方承认是他们的错误却拒绝退款（G2 原话两条）。
  • 权限模型有洞：Team Administrator 也改不了别人名下文件的权限，所有者离职即失去文件；原话里那句自嘲很扎心——I am the team administrator. I guess I contact myself?
  • 大文件会卡：组件库多、画板复杂时明显掉帧与吃内存，多人协作重度时甚至崩标签页（G2 原话）。
07

商业模式 & 变现

怎么赚钱
收入模型
按席位订阅 + AI credits 加购

四档订阅（Starter 免费 / Professional / Organization / Enterprise），每档三类席位分别定价（Full / Dev / Collab），每席位附赠定量 credits；AI 能力超出即加购或按量付费，组织版另售安全与合规能力。

免费 ↔ 付费 分水岭
免费停在哪

Starter：草稿不限、正式设计文件与团队能力受限，AI credits 每日 150、每月上限 500，inspector（Dev Mode）不可用（G2 原话点名此限制）。Professional 起才有无限文件、高级 Dev Mode 与 MCP Server、3,000 credits/月（Full seat）。付费档可让非付费者查看与评论，不必买额外席位——这条是它的传播机制，也是误计费的源头。

变现入口
入口免费，钱收在「席位类型」上

Starter 免费且不限草稿、可无限评论；一旦要无限文件、Dev Mode 与团队权限就进 Professional。真正精细的地方是把席位拆成三类：只做设计的买 Full，只看代码的买 Dev（12 美元），只评论的买 Collab（3 美元）——同一团队可以按角色付不同的钱，这是它比「按人头一刀切」更聪明、也更容易算错的地方。

体验 ↔ 变现 是否同向
体验与变现是对齐的，还是打架的？

局部对齐，结构上打架。对齐的一面：协作免费、评论免费，先把人拉进同一个文件，再按角色收席位——收费点正好落在「这个人开始真正干活」的时刻。打架的一面：分享即协作，协作即可能计费，于是「拉人进来看看」这个最自然的行为会悄悄变成账单（14 个月那条投诉就是它），而权限又卡在文件所有者手里，用户在同一个模型上同时感到「方便」和「说不清」。

增长策略

明牌或推断

主要获取渠道

  • 社区与作品集：公开文件、设计系统、插件构成可搜索的长尾入口，作者发布即分发。
  • 产品发布驱动：Product Hunt 36 次 Launch、15K 关注、4.9 分（1,609 条评价），每次新能力（Agent、Specs、Code Layers、Motion）都自带一次曝光。
  • 自下而上的团队渗透：一个人把文件发给同事，评论免费、编辑收席位——增长最快的一条，也是账单最容易出错的一条。

主要增长循环

  • 团队渗透环 — 一个人拉一个文件 → 别人只能进来评论 → 评论者变成编辑 → 席位增加。这条环很有效，也很容易失控：G2 那条「外部人被算成 full member 收了 14 个月」就是这个环的反面。
  • 社区文件环 — 公开文件与插件被复制使用 → 作者获得曝光 → 更多人把作品放上来 → Community 成为搜索入口。G2 好评原话：What stands out most is the Figma Community… thousands of open-source design systems, UI kits, wireframes, and icons。

扩张向量

横向
  • 从设计到交付：Dev Mode、Code Layers、Specs、MCP——把开发也拉进同一个文件。
  • 从设计到生成与上线：Make、Sites、Buzz、Motion、Draw——把「做完设计之后」的事也接住（[推断] 这是它对 Framer 与 Lovable 的正面回应）。
纵向
  • 产品与互联网团队：设计系统、组件库、设计到开发交付；代理商按客户项目协作。
  • 品牌与营销物料：Buzz 批量出品牌素材，Slides 出提案——把非产品设计的场景也吃进来。
平台
  • 开放接口已存在：MCP server（mcp.figma.com/mcp）让外部 agent 读设计上下文、写代码与内容；插件生态与 REST API 多年积累。
  • [推断] 平台策略是「文件即协议」：不做交易抽成，靠文件格式、权限模型与插件接口把第三方能力长在自己身上；MCP 是把这个协议开放给 AI 的那一步。

应用层六维

模型用得好不好

六维是本系列的主框架：前三条看值不值，后三条看敢不敢用、会不会留下。

本片判为 **嵌入**。拔电测试：拿走 AI，产品照常卖 → AI 嵌入。（依据：传统工具，AI 属后加能力）

① 替掉哪一步

它替掉的是「把想法变成可评审的稿」这一段里最耗人的部分：找组件、摆版式、对齐状态。原来设计师做（现在也还是设计师做），只是从几轮来回压成一次生成 + 手改；成本从人工时间变成 16 美元订阅加 132 积分一次。实测（燃冰）的原话是：省的是设计师找组件模板这一段。

② 脏活谁干

脏活它啃掉了一半：页面结构、状态保留、颜色体系、免责声明这类「照原稿来」的活它自己处理；甩回来的是一句——甩回来的是设计师自己的判断。所以它要求人把「我要什么」说清楚（左侧抽屉、金融卡片、红涨绿跌），说不清就做不对。这道门槛不是软件的，是表达与审美的。

③ 出来能不能用

能用。实测结论：能用，可以改图层；但会不会有人拿它直接对外发——不会，我觉得还是需要专业人士的。也就是说，它交回的是「可继续加工的成品」，不是「终稿」。

④ 错了怎么兜

兜底很薄：它会提示这是假数据、需要接入真实数据，但对「你给的前提就是错的」这件事它不管（实测原话：它不管这个），给错前提它会顺着做，还会提示将新开页面操作。没有来源标注、没有置信度，最终靠人工复核。

⑤ 错一次多贵

错得起。结构可拆到图层，能撤回，也有历史记录（实测：能撤回）；真正的成本是 credits——一次页面 132 积分，免费额度四次出头就用完。所以「错一次多贵」在它这里不是数据风险，是额度消耗。

⑥ 不用它的替代

换得掉，但习惯在那。实测的原话：换得掉，但习惯在那——它相对 Framer 更偏设计资料沉淀、能导出代码原型；插件也能调用，但有使用个数限制。明天它消失，顶上来的还是设计师本人。

他们真正在优化什么指标

[推断] 北极星 + 护栏

官方未公开运营指标。以下分两类：能核实的公开事实，与标注 [推断] 的「它应该看什么」，不是真实数据。

北极星
周活跃文件数 × 每文件每周多人协作次数（[推断]）

[推断] 它按席位收费、按文件承载协作：文件数决定席位上限，多人协作次数决定席位会不会真的被买。所以北美星不是「注册设计师数」，而是「同时在同一个文件里干活的人数」。

输入指标 · 1
免费档到付费席位的转化（按席位类型拆）

Starter 不限草稿、可无限评论，付费墙立在「无限文件 + Dev Mode + 团队权限」上；Full / Dev / Collab 三类席位的转化率分开看，才知道收入是从设计师来还是从旁观者来。

输入指标 · 2
credits 消耗与加购率

AI 收入全压在 credits 上（3,000 / 3,500 / 4,250 起，超出加购）。实测一次页面 132 积分，免费额度四次出头就用完——加购率高说明 AI 真在用，也预告账单抱怨会同步上升。

输入指标 · 3
席位误升级率与退款申请率

这是它独有的关键指标：分享即可能计费，所以「自动升成成员」的比例直接决定口碑与客服成本。G2 那两条投诉说明这个数字曾经很高。

护栏指标
账单类投诉占比 + 权限/资产类工单量

G2 4.7 分与成堆的负面反馈同时存在（该字段连 4–5 星用户也会填），说明产品满意不等于商业满意。这两条是唯一能区分「设计口碑」与「收钱口碑」的护栏。

盲区
没有公开的留存曲线、席位流失率、毛利率，也没有 credits 的单位推理成本 [推断]

[推断] 它同时卖订阅与卖推理：只盯营收不盯单位成本，会看不见「AI 越普及毛利越薄」的风险。另一边，权限与账号风控造成的资产损失不进入任何公开指标，却是最伤留存的一类事件。

机会 & 重设计

可落地的 PM 思考
改进 · 1
（我的判断）把「谁让我多付了钱」做成事前提示
怎么做：有人被拉进文件时，先显示「加入后会占哪类席位、会影响本月多少钱」，并给一个「只评论」的默认值。为什么：G2 的席位投诉不是价格太高，是不知道什么时候开始计费；这一改不需要动产品架构，是最便宜的信任修复。
改进 · 2
（我的判断）把「132 积分一次」变成可见的预算条
怎么做：生成前面板显示本次预估消耗与剩余 credits，接近上限时提示「这一版会用掉剩下的一半」。为什么：实测（燃冰）第一次用完免费额度时是没预警的；对一人公司，可预期比便宜更重要。
改进 · 3
（我的判断）把文件所有权从「个人」解耦成「团队」
怎么做：允许团队管理员强制接管离职成员名下的文件与权限，并在成员停用时给出导出提醒。为什么：G2 那条「账号被关、三年工作没了」是最贵的一类失败——它损失的不是一个用户，是这个人所有的作品与口碑。
战略转向
它的赌注：用协作网络锁住团队，用 AI 把「做完设计之后」也吃下来
两个赌注同时下：一是把设计、交付、生成、上线全部挂到同一个文件上（Dev Mode、MCP、Make、Sites），让「换工具」等于「换协作方式」；二是把 AI 做成 credits 型附加收入，而不是主路径替代。第一个赌注加固护城河，第二个保住毛利——但两者叠加会让「账单为什么这么高」变成长期问题，因为 AI 用得越多，账单越难解释。
🌙 登月构想
终局：让「设计」这个环节不再需要交接
如果 agent 能读懂设计意图、生成可维护的组件、直接产出可上线代码与规格，那么设计师、前端、产品之间的三次翻译会塌缩成一次。距离不在模型能力，在「谁负责审」——实测（燃冰）已经指出：它不纠错前提，判断仍归人。所以终局的瓶颈是信任与责任，不是生成质量。

终局判断

综合判定
为什么它赢

多人实时同文件的网络效应、组件与设计系统的资产沉淀、Dev Mode 把交付拉进同一份文件、Community 与插件构成的分发长尾。

在哪里断裂

要源码主权、必须自己部署的团队（会去 Lovable / v0 / Claude Code）；预算极紧或要求自主可控的（Penpot / 自托管）；只需要「设计完直接上线」的（Framer）；以及把文件所有权安全当硬要求的代理商——所有者离职就丢文件这条，足以否掉一单。

长期护城河

护城河真实存在，但位置很具体：不在模型，在「协作网络 + 组件沉淀 + 交付标准」三件套。前两件是时间与习惯堆出来的，第三件是行业默认值。AI 只加固了第三件的一小段。所以它的护城河不会被模型追平，只会被「新人从代码起手、压根不用设计工具」这种路径变化绕开。

[推断] 真护城河不在模型层（模型能力外部可得，Make 的生成质量不是它最难复制的东西），而在「实时协作的同步内核 + 文件格式成为行业默认 + 组件资产沉淀」三者的耦合。这三样都得靠时间与用户习惯堆，买不到也追不快。反过来说，AI 生成这条能力最容易被追平，所以它把 AI 做成 credits 而不是主卖点——这是清醒的。

可迁移的机会（我的判断）

附录 A
  1. 把「加入即计费」做成事前提示——有人被拉进文件之前，先显示他会占哪类席位、本月多花多少，默认只给评论权。G2 两条独立投诉（14 个月、重复收费不退）都出在这里；对一个一人的投资工具产品，这就是「用户不知道钱怎么涨的」那一类失败，最伤信任。最轻，一个弹层加一次确认。
  2. 把 credits 变成可见预算条——生成前显示预估消耗与余额，接近上限时警告。实测（燃冰）第一次用完免费额度是没有预警的；一人公司可预期比便宜重要。
  3. 把「生成」做成带 diff 的审阅——每次 agent 改动列出动了哪些组件与状态。实测的关键一句是「可以改图层」，但没告诉人改了什么；审阅能力决定人敢不敢放手。
  4. 把文件所有权与个人解耦——团队可强制接管离职成员的文件，停用前给导出提醒。这条对代理商是成交门槛。

四个里哪个最轻？第 1 个：不需要动产品架构，只改一个默认值和一句提示。哪个最贵也最值？第 4 个：它决定的是「敢不敢把整个设计资产放进来」，而这正是订阅制最想要的答案。

价格结论（我的判断）：单人场景下 Figma 的 16 美元与 Framer 的 10–15、Sketch 的 12 是同一量级，不贵；贵在「按人涨」。五个人的团队按 Figma 算 5×16＝80 美元，按站点计价的 Framer 只要一个站点加一两个编辑席位；但 Framer 的编辑席位也按人收，团队一多同样陡。所以真正的差别不是单价，是计价轴：Figma 按人头，Framer 按站点。谁的团队里「做设计的人少、看的人多」，谁的账单就轻——这恰好解释了 Figma 为什么要拆出 Dev 与 Collab 两类席位。

流量吃长尾：Community 公开文件与设计系统是可搜索的入口，作品集与设计教育持续供人，产品发布（PH 36 次 Launch、15K 关注）负责波峰。变现三段：订阅（广度）→ 席位类型（厚度）→ credits 与加购（深度）。最脆的一根梁是「分享免费、协作可能计费」与「文件归个人所有」这两条同时成立：前者让账单自己长出来，后者让资产归属说不清——G2 的低分几乎全落在这两根梁上。
